## 1. Weekly Production Cycle

A repeatable weekly rhythm, not a one-off checklist — run this every week.

### Step 1 — Plan (start of week)
1. Open `context/Marketing_Strategy.md` Section 1.3 — confirm which series is due each day this week (check week parity if the rotation is bi-weekly).
2. For each series, note the required format per Section 1.4's volume targets.
3. Batch-list the week's core content plus daily ephemeral-content ideas.

### Step 2 — Draft
1. Write the caption/copy first, before touching design/video tools. Apply:
   - Voice/tone rules for the specific pillar (`Style_Guide.md` Section 3.2)
   - The language/register rules (`Style_Guide.md` Section 3.3)
   - Standard terminology per `Glossary.md` (with the pairing rule, if defined)
2. Every educational/informational post ends with an engagement prompt per the Style Guide's writing rules (Section 4).

### Step 3 — Produce
1. **{{FORMAT_1}}:** {{TOOL_1}} — use the saved brand template; duplicate, drop in content, don't redesign from scratch each time.
2. **{{FORMAT_2}}:** {{TOOL_2}}.
3. **Ephemeral content:** native platform tools are usually fine — no dedicated design tool needed.

### Step 4 — Quality Check (before publishing)
Run the checklist in Section 2 below on every piece of content before it goes live. Do not skip this step even when short on time — it's the fastest place to catch a wrong term or off-brand color.

### Step 5 — Publish
1. Post at the scheduled day/slot per the rotation.
2. If a scheduler tool is adopted later, queue the week's batch at Step 3 completion instead of publishing manually — update this step once that tool is confirmed (`Marketing_Strategy.md` Section 7).

### Step 6 — Monitor & Respond (daily, ongoing)
Apply the Community Guidelines (`Marketing_Strategy.md` Section 8) as comments/DMs come in:
- Rudeness/gatekeeping between commenters → per the moderation policy (harassment always gets reported/removed)
- Spam → remove only if clearly spammy
- Product questions → use the holding response until pricing/specs are locked (`Products.md`)

## 2. Pre-Publish Quality Checklist

Run through this on **every** piece of content before it goes live:

- [ ] Correct series for the day, per the rotation
- [ ] Caption tone matches the pillar (`Style_Guide.md` Section 3.2)
- [ ] Terminology matches the glossary exactly — no ad hoc alternate terms
- [ ] Term-pairing rule applied on first mention (if defined in `Glossary.md`)
- [ ] Colors used are only the locked palette (`Style_Guide.md` Section 2.1)
- [ ] Typography is the locked pairing (`Style_Guide.md` Section 2.2) — no substitutions
- [ ] Caption ends with an engagement prompt (educational) or a clear narrative hook (storytelling)
- [ ] No product claims beyond what's confirmed in `Products.md`
- [ ] Alt text / keyword-rich caption language included (platform discovery is keyword-based)

## 3. Monthly Review Ritual

Once a month, step back from daily production and check the strategy against reality:

1. **Pull performance data** — which series/posts scored best on the priority metrics (`Marketing_Strategy.md` Section 1.4). The `data-analyzer` skill / `sop/SOP_Data_Analysis.md` is how this data work gets done.
2. **Compare against growth benchmarks** — check current numbers against the Section 2 table. This isn't pass/fail, it's a sanity check on pace.
3. **Flag any signal for the audience checkpoint** — per Section 4.1's adjustment plan; if one segment's series consistently outperform, start preparing the rebalance — don't wait for the exact calendar date if the data is already clear.
4. **Note anything to update in the living docs** — if a decision was made ad hoc during the month, write it into the relevant file immediately rather than letting it live only in memory/chat history.

---

## 4. Escalation / Exceptions

A few situations warrant pausing the normal weekly cycle:

- **Genuine harassment or abuse in comments** → report via platform tools immediately, don't wait for the weekly cycle.
- **A post performs unexpectedly well or poorly** → make a note immediately so the signal isn't lost by the monthly check.
- **A product question that the holding response can't cover** (bulk/wholesale inquiry, partnership pitch) → handle case-by-case until `Products.md` and the partnership strategy are more developed.

## 5. Document Maintenance

These MD files are living documents. Whenever a real decision is made (in chat or elsewhere):
1. Update the relevant file (Context / Products / Marketing Strategy / Style Guide / Glossary) immediately.
2. Mark the corresponding open item as resolved in that file's checklist.
3. If the decision affects daily production, also update this SOP's relevant step.

**Principle: if it's not written in one of these files, it doesn't count as decided** — chat history isn't a substitute for the docs.
